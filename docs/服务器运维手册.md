# 服务器运维手册

**保密等级：秘密 | 版本：3.2 | 生效日期：2026-03-01**

## 1. 服务器清单

### 生产环境
- 12个Kubernetes集群节点
- 2台负载均衡器（Nginx）
- 3台MySQL数据库服务器（1主+2副本）

### 预发环境
- 4个节点，1台MySQL，1个Elasticsearch节点

### 开发环境
- 2个节点，共享服务

### 配置规格
- 所有服务器：Ubuntu 22.04 LTS，64GB内存，16核CPU，500GB SSD存储

## 2. 监控与告警

- **监控栈**：Prometheus（指标采集）+ Grafana（仪表盘可视化）
- **关键仪表盘**：CPU利用率、内存使用率、磁盘I/O、网络吞吐量、应用延迟百分位
- **告警规则**：
  - CPU > 80% 持续5分钟
  - 内存 > 85%
  - 磁盘使用率 > 90%
  - API p99延迟 > 3秒
- **告警渠道**：内部即时通讯平台（所有告警），SMS通知（P1/P2严重事件）
- **值班轮换**：每周轮换，指定主值班和次值班人员

## 3. 备份策略

- **MySQL**：每日凌晨2:00全量备份，每6小时增量二进制日志备份，保留30天
- **ChromaDB/Elasticsearch**：每日凌晨3:00集合/索引快照，保留14天
- **备份验证**：每周自动恢复测试至预发环境
- **异地备份**：每日通过安全通道将加密备份传输至AWS S3（ap-southeast-1区域）

## 4. 安全加固

- **SSH访问**：仅密钥认证（禁用密码认证），端口22仅限内部VPN IP地址范围
- **防火墙**：UFW（默认拒绝入站策略），仅开放必要端口：443（HTTPS）、8082（应用）
- **安全更新**：关键安全补丁在厂商发布后24小时内应用，常规更新在每周维护窗口进行
- **审计**：每月使用自动化工具进行漏洞扫描，每季度由认证安全公司进行外部渗透测试

## 5. 事件响应

| 级别 | 响应时间 | 解决时间 |
|------|----------|----------|
| **P1（严重 - 服务中断）** | 15分钟内 | 4小时内 |
| **P2（高 - 性能降级）** | 1小时内 | 24小时内 |
| **P3（中 - 非关键问题）** | 4小时内 | 72小时内 |
| **P4（低 - 小问题）** | 24小时内 | 2周内 |

- **事后审查**：事件解决后5个工作日内完成，包括根因分析、时间线和预防措施计划

## 6. 容量规划

- 每月进行容量审查，含趋势分析和预测
- **扩缩容触发条件**：任何资源（CPU、内存、磁盘、网络）在7天内平均利用率超过70%
- **扩容流程**：Web/应用层自动水平扩展（Kubernetes HPA），数据库层手动协调扩展（需CTO批准）
- **采购周期**：标准服务器硬件需2周
